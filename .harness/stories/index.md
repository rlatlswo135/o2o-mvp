## 업무 스토리 후보

아래는 범위·의존성 목록이다. 완료 판정은 해당 checkpoint, 진행 중 세부 상태는 CURRENT에서 확인한다.
S001의 FE 확인만으로 전체 완료·후속 의존성 충족을 선언하지 않는다. [사용자 BE 가이드](S001R2/be-guide.md), [현재 범위](S001R2/story.md).
AI는 FE, 사용자는 BE·구성을 담당한다. 실고객 데이터는 인증·접근 보호와 운영 준비 후에만 사용한다.

| 순서 / ID | 스토리 | 확인할 결과 | 선행 |
| --- | --- | --- | --- |
| 1 / S001 | [고객 등록 → 목록 확인](S001R2/story.md) | 이름·전화번호 저장, 새로고침 후 유지. 동일 번호는 등록 요청에서 서버가 차단 | 사용자 담당 기반 |
| 2 / S002 | 고객 기본정보 수정 | 선택한 고객의 이름·전화번호 수정 후 다시 조회. 동일 번호 중복 규칙 유지 | S001 |
| 3 / S003 | 사장님 로그인·로그아웃과 고객정보 접근 보호 | 로그인 상태에서 자기 샵 고객을 조회하고, 로그아웃 후 접근 불가. 직원 계정 없음 | S001; 인증 방식은 착수 시 결정 |
| 4 / S004 | 담당자 등록·수정·비활성화 | 사장님 포함 담당자를 관리하고 현재 예약 배정 대상 확인. 과거 기록은 보존 | S003 |
| 5 / S005 | 시술 기본정보 관리 | 시술 이름·기본 소요시간·기본 가격을 저장하고 목록에서 확인 | S003 |
| 6 / S006 | 담당자별 시술 시간·가격 설정 | 별도 값이 있으면 우선 사용, 없으면 시술 기본값 사용 | S004, S005 |
| 7 / S007 | 담당자 기본 근무시간 설정 | 반복되는 요일별 근무시간 저장·재조회 | S004 |
| 8 / S008 | 특정 날짜 근무시간 변경 | 지정 날짜의 출퇴근 시간·휴무 변경 후 기본 일정과 구분해 확인 | S007 |
| 9 / S009 | 단일 시술 예약 등록 → 오늘 타임테이블 확인 | 고객·담당자·시술·시작시간을 선택해 저장. 담당자 일정 확인, 근무시간·예약 충돌 검사, 담당자별 소요시간 적용 | S001, S006, S008 |
| 10 / S010 | 여러 시술을 조합한 예약 등록 | 선택한 시술들의 담당자 기준 소요시간을 합산해 전체 구간 검사·저장 | S009 |
| 11 / S011 | 날짜를 선택해 예약 조회·등록 | 오늘 외 날짜의 타임테이블을 확인하고 해당 날짜에 예약 등록 | S009 |
| 12 / S012 | 예약 날짜·시간 변경 | 다른 빈 구간으로 이동. 충돌하면 변경 실패, 기존 예약 유지 | S011 |
| 13 / S013 | 예약 담당자 변경 | 대상 담당자의 일정 확인, 소요시간 재계산 후 전체 구간 충돌 검사 | S010, S012 |
| 14 / S014 | 예약 취소와 취소 기록 확인 | 사유·시각·원래 내용을 보관하고 기본 타임테이블에서 제외. 점유한 시간 해제 | S009 |
| 15 / S015 | 예약 완료 처리 | 완료 시각을 기록하고 완료 여부 확인. 회원권 자동 차감은 포함하지 않음 | S009 |
| 16 / S016 | 일회성 시간 차단·해제 | 담당자 또는 샵 전체의 특정 구간·하루를 차단하고 비고 기록. 기존 예약과 겹치면 차단 불가 | S011, S014 |
| 17 / S017 | 반복 시간 차단 관리 | 반복 규칙에 따라 해당 날짜의 예약 가능 구간에서 제외하고 변경·해제 가능 | S016; 반복 주기·예외 정책은 착수 시 결정 |
| 18 / S018 | 고객의 현장 결제 기록 | 실제 받은 금액을 고객에 연결해 기록·조회. 서비스 내 결제 처리 없음 | S001, S003 |
| 19 / S019 | 회원권 충전 → 잔액·이력 확인 | 고객별 합산 잔액 증가, 충전액과 실제 결제액을 구분해 저장·조회 | S018 |
| 20 / S020 | 회원권 잔액 직접 증감·이력 확인 | 시술 사용·과충전·과차감 등을 금액 증감과 사유로 처리. 전후 잔액·시각·사유 기록, 매출 불변, 마이너스 잔액 금지 | S019 |
| 22 / S022 | 회원권 일부 사용 + 부족분 결제 기록 | 잔액 범위에서 차감하고 나머지 실결제 기록. 매출에는 실제 받은 금액만 반영 | S018, S020 |
| 23 / S023 | 결제·매출 금액 증감 정정 | 사장님이 대상 기록의 금액을 조정하고 변경 이력·사유 확인. 회원권 잔액 불변 | S018, S019 |
| 24 / S024 | 회원권 해지 환불 기록 | 실제 환불액 입력, 합산 잔액 전부 소멸, 원거래·환불 이력 유지. 실제 환불액만 매출에 차감 | S019, S020 |
| 25 / S025 | 월별 실제 결제액 대시보드 | 선택한 월의 실제 결제·금액 정정·환불을 반영한 합계 확인. 회원권 사용 중복 집계 없음 | S018, S019, S023, S024 |
| 26 / S026 | 고객별 실제 결제액 확인 | 선택 고객의 동일 기준 합계와 근거 거래 확인 | S025 |
| 27 / S027 | 예약 안내 문구·발송 시각 설정 및 테스트 수신 확인 | 제공사가 허용하는 문구 설정을 저장하고, 사용자 소유 테스트 번호에서 안내 메시지 확인 | S003; 사용자 발송 서비스 계정·승인된 템플릿 필요 |
| 28 / S028 | 전날 예약 안내 자동 발송 | 설정한 시각에 다음 날 대상 예약 안내 발송. 취소 제외, 최신 예약 반영, 중복 발송 방지와 실패 확인 | S010, S011, S013, S014, S027 |
| 29 / S029 | 사장님 화면 테마 선택·유지 | 제공된 시각적 테마 변경 후 다시 접속해도 유지. 배치·기능 구성은 고정 | S003; 테마 옵션은 사용자 디자인 리뷰로 결정 |

한 번에 한 스토리만 승인한다. 미정 정책은 착수 시 상세화하며 구현·커밋·푸시는 별도 승인이다.
이전 인덱스의 논의·인계 이력은 [보존본](index-history.md)에 있다. 기본 재개 시 읽지 않는다.
