# 시안 기준 공통 UI 잔여 범위

## 목적과 기준

사용자 요청: 기존 Field·Input·Button을 직접 확인했고 현재 구현으로 충분하므로, 이 세 컴포넌트는 구현된 전제로 남은 공통 UI를 계획한다. 이는 S001 고객 기능의 완료 승인이나 새 구현 승인이 아니다.

- 시안: [입력·조작](../design/images/ui-01-inputs.png), [표시·피드백](../design/images/ui-02-feedback.png). executor는 이미지를 실제로 열어 확인한다.
- 기존 세 컴포넌트와 토큰을 재사용한다. 기존 Button에 회색 채움 variant를 추가하거나 Field/Input API를 재설계하는 일은 포함하지 않는다.
- 신규 UI 작업은 S001 고객 기능과 분리한다. 아래 네 스토리를 모두 사용자 확인하기 전에는 '시안의 남은 공통 UI 완료'라고 하지 않는다.
- 기존 S001의 승인 문서·미해결 게이트는 그대로 보존한다. UI 스토리 완료로 고객 등록·DB 연결·기존 학습 게이트를 완료 처리하지 않는다.

## 공통 구현 경계

- 위치: `client/src/shared/ui/`, 소문자 파일명. `features/`·`routes/` 의존 및 고객/예약 업무 규칙 금지. 문구·옵션·상태·콜백은 소비자가 전달한다.
- `client/src/routes/index.tsx`의 기존 검토 화면만 단계별로 확장한다. 가상 데이터·로컬 상태로 조작을 확인하며 API·영속 저장·업무 화면·새 라우트·전용 카탈로그 도구는 추가하지 않는다.
- 기존 StyleX 토큰 재사용. 성공·경고처럼 실제 신규 UI에 필요한 의미 토큰만 추가하고 기존 토큰 값·Field/Input/Button 계약은 유지한다. 불가피한 기존 계약 변경은 먼저 사용자와 범위를 확인한다.
- 네이티브 HTML로 가능한 입력·선택·표를 우선한다. 복합 상호작용은 설치된 flame-ui 1.0.1의 실제 API·접근성을 확인해 재사용한다. 새 패키지·DOM 테스트 도구·설정 변경·server/ 수정·커밋·푸시는 제외한다.
- 선택 요소의 테마 예시는 단일 선택 상태만 보여준다. 실제 앱 테마 변경/저장(S029)은 제외한다.
- 시안은 배치·색·상태 기준이지 픽셀 단위 복제 계약이 아니다. 작은 화면에서도 조작 가능해야 하며 네이티브 메뉴의 OS별 외형 차이는 허용한다.

## 영향과 회귀 확인

현재 직접 소비자는 `routes/index.tsx` 한 곳이다. Input은 Field의 `useFieldControl`·`joinIds`를 사용한다. 새 Select/Textarea/금액 입력은 동일한 label·description·error 연결을 재사용하며, Radio 그룹에는 단일 입력용 Field를 억지 적용하지 않는다.

공통 토큰 추가의 영향 범위는 모든 기존 UI다. 기존 토큰 삭제·변경 없이 확장한다. 기존 SSR 테스트는 Button 3개·Field/Input 6개이며 상호작용 회귀는 보호하지 못한다. 새 기능의 자체 판단/변환은 작은 자동 테스트, 키보드·포커스·클릭·알림은 executor 브라우저 검증으로 보완한다. 위험: 중간(새 접근성 연결·금액 입력·overlay 동작, DOM 자동 검증 없음).

## 각 스토리의 필수 검증·완료 게이트

- executor는 착수 시 실제 명령과 기준을 확인한다. client에서 `vp check`, `vp test --run`, `vp run build`를 실행하고 실제 결과를 기록한다. 변경 파일 검사와 기존 전체 검사 실패를 분리한다. 실패·미실행·coverage 미구성을 PASS로 쓰지 않는다. 설치가 필요하면 승인부터 받는다.
- 테스트는 네이티브 prop 전달 자체보다 자체 분기·상태 매핑·ARIA 연결·변환을 확인한다. 기존 9개 테스트를 유지한다. DOM 테스트 라이브러리는 추가하지 않는다.
- executor는 dev 및 production preview에서 CSS 적용을 확인하고, 해당 스토리 완료 조건을 브라우저로 검증한다. 예전 dev CSS 결함이 현재도 있다고 단정하지 말고 실제 상태를 확인한다.
- 키보드 조작·보이는 포커스·접근 가능한 이름·오류 연결·disabled 상태·작은 화면(약 375px)을 직접 확인한다. 표만 필요한 가로 스크롤을 허용하고 페이지 전체 넘침은 방지한다.
- 정확한 revision의 구현 승인 → 구현/QA 증거 → 고정 기준 리뷰와 사용자 리뷰 결정 → 사용자 화면 확인 → 최종 완료 확인. 자동 DONE 금지.
- 신규 공통 UI 스토리에 학습 문서를 강제하지 않는다(사용자 선택 없음). S001의 기존 학습 게이트는 삭제·면제하지 않는다.
- 코드리뷰/Fix·executor QA/Fix 각각 최대 3회, 같은 실패 연속 2회면 blocked. 미선택 수정안을 자동 적용하지 않는다.
- 진행·증거는 각 `implementation.md`, 리뷰는 `review-N.md`·`review-brief.md`, 상태는 런타임 checkpoint에 기록한다. 승인 후 story.md와 승인 범위를 정의하는 본 문서의 해당 조건을 임의 변경하지 않는다.
